# 隐翅虫皮炎分级响应热线

雨后隐翅虫皮炎就诊增多场景下的社区健康热线后端。它在**严格边界**内工作：
只收集最少必要的结构化事实，给出清水/肥皂水冲洗等标准化即时提示，
把大面积红斑、水疱、密集脓疱、糜烂渗出等危险信号升级到人工坐席或线下就医；
**线上输出在任何情况下都不构成诊断。**

## 边界（设计红线）

- 不接收照片、附件、详细地址与自由文本：区域只接受编码（如 `R001`），事实字段必须是规则包登记的枚举/标量。
- 资料不足、事实无法解释或前后矛盾时，固定升级为`人工复核`，**绝不输出低风险结论**。
- 已报告的危险信号在资料不足时仍然升级（兜底只抬高下限，不拉低证据支持的等级）。
- 事件一旦因证据升级，后续补充资料不能由自动流程降级（`S-MONOTONIC`），降级只能由人工判断。
- 每次回复都返回并落库：规则版本、命中规则 ID、当时事实快照、缺失/异常/矛盾事实与边界声明。
- 同一联系方式的重复来电合并到家庭下的原事件；错误偏方（牙膏、酒精、碘伏等）的发出、重复、确认停用全程留痕。
- 趋势按去重家庭计数，公开发布前过两道闸：区域常住人口下限与 k-匿名格子抑制（k=5）；抑制格不渲染为 0。
- 聚集性告警按区域×72 小时对齐窗口去重，数据库唯一约束保证同一窗口**只有一条**告警。
- 联系方式只存加盐 SHA-256 哈希（盐存于数据库 meta 或 `HOTLINE_SALT` 环境变量），库中任何文本字段都不含原始号码。

## 模块

| 文件 | 职责 |
|---|---|
| `rules/pack-1.0.0.json` | 唯一事实来源：枚举、危险偏方与纠正话术、安全提示、分级规则、不足兜底、k-匿名/聚集参数 |
| `rules/README.md` | 规则版本化与调整流程（已发布包不可变，调整即升版本） |
| `triage_rules.py` | 规则包加载校验、事实归一化、分级判定（无医学结论硬编码） |
| `store.py` | SQLite：家庭/事件、追加式事实、响应审计、纠正轨迹、唯一告警 |
| `hotline.py` | 接报编排：家庭合并、事实重放与矛盾检测、单调升级、坐席动作 |
| `analytics.py` | 去标识化趋势与聚集扫描（只读聚合，不接触描述文本） |
| `service.py` | HTTP 入口与 `--check` |
| `domain.json` | 公共分类法；`--check` 与单元测试强制规则包覆盖其全部取值 |

## 使用

```bash
python3 service.py --check                 # 校验规则包结构及与 domain.json 的一致性
python3 service.py --db data/hotline.db \
    --populations regions.json --port 8000 # regions.json: {"R001": 80000, ...}
python3 -m unittest -v                     # 33 项测试
```

### 主要接口

- `POST /v1/intake`
  ```json
  {"contact": "13900000001", "region": "R001",
   "facts": {"疑似虫体接触": true, "部位": ["四肢"],
             "皮损表现": ["线状红斑", "灼痛"], "已采用处理": ["牙膏"],
             "症状持续小时": 6},
   "stopped_treatments": ["牙膏"]}
  ```
  返回等级、标准化提示文本、偏方纠正及追踪动作、仍需补充的事实、
  命中规则与规则版本、边界声明；重复来电返回同一`事件号`并标记`合并于原事件`。
- `GET /v1/events/{event_id}`：处置轨迹（事实批次、每条回复的审计记录、纠正轨迹）。
- `POST /v1/agent/transition`：人工坐席流转状态（含关闭事件）。
- `GET /v1/trends?since=<unix秒>&until=<unix秒>`：仅含 k-匿名后的区域×天计数。
- `POST /v1/clusters/scan`：扫描当前窗口聚集，新建告警在`新建告警`，重复扫描不产生第二条。
- `GET /health`：服务身份与当前规则版本。

建议等级：`立即冲洗`（与任何更高等级并行给出）→ `居家观察` → `人工复核` → `尽快就医`。

## 规则调整流程

分级口径变化 = 复制出新 `pack-x.y.z.json` 并升版本，`--check` 通过、评审后发布；
历史回复永久保留其当时的规则版本与事实快照，可按当时规则复算。详见 `rules/README.md`。
